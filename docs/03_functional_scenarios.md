# 2 Функциональные сценарии использования

## 2.1 Акторы системы

Система определяет следующих акторов:

- **Студент** — участник олимпиады, проходит регистрацию, выполняет задания, проходит прокторинг
- **Организатор** — создаёт и администрирует олимпиады, управляет вопросами и участниками
- **Администратор** — управляет пользователями и их ролями
- **Система (прокторинг)** — автоматический мониторинг активности студента во время участия

---

## 2.2 Сценарии использования студента

### UC-1: Регистрация через Google OAuth

**Описание:** Студент проходит регистрацию и аутентификацию в системе через Google OAuth 2.0.

**Предусловия:** Студент имеет аккаунт Google.

**Основной поток:**
1. Студент нажимает кнопку «Войти через Google» на странице входа
2. Система перенаправляет на страницу авторизации Google
3. Студент предоставляет разрешения системе
4. Google перенаправляет обратно с кодом авторизации
5. Система создаёт/обновляет пользователя и выдаёт JWT-токены
6. Студент перенаправляется на главную страницу

**Ожидаемый результат:** Студент получает доступ к системе, данные профиля заполняются из Google.

**REST API:** `GET /api/auth/oauth2/callback/google`

**Frontend:** `LoginPage.tsx`, `authStore.ts`

**Статус тестирования:** Backend unit-тест отсутствует, проверено E2E
